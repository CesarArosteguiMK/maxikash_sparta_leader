¿Qué hace este módulo?

Gestiona archivos de reportes en el servidor remoto usando solo esta API (agente). La clave SSH está dentro del agente; no depende de carpetas ni permisos de Sparta Ledger.

  • Historial: hoy y ayer; proveedor / nosotros (root).
  • Copiar +1s: copia en el servidor con nombre +1 segundo.
  • Descargar / Eliminar: solo nosotros (root) puede eliminar.
  • Truncar: no disponible en modo agente (requiere BD en Sparta Ledger).
Resumen de botones y alertas

¿«Listar archivos» es para actualizar? Sí. Vuelve a pedir al agente la lista (GET /files) y refresca la tabla. Úsalo cuando quieras ver archivos nuevos o cambios.

Estado en BD: En el Shell de Sparta Ledger hay una columna con un icono (✓/✗/procesando) que indica si el reporte ya está cargado en la base de datos. En esta vista del agente esa columna no aparece porque el agente no tiene MySQL; solo muestra lo que hay en el servidor de archivos. Cuando integres el agente con Sparta Ledger, esa información se puede volver a mostrar si el backend consulta la BD.

Al abrir el .bat solo se inicia el agente. Con el interruptor en «Activar»: la copia automática ocurre a las horas indicadas; el truncar semanal automático se intenta los martes entre 07:00 y 09:29 CDMX hasta completarse (máximo una vez por martes). Refuerzo BD: ventana tras cada xx:40 CDMX. Nocturno: el agente comprueba en BD el archivo mega_rpt_…_23_52_00 (hora en el nombre del ZIP) a las 23:52 CDMX y, por si acaso, otra ventana a 00:05 del día siguiente; en la tabla semana ese corte se guarda en columnas como Dias_mora_*_23_50 (nombre de columna en la BD, distinto del 23_52 del archivo). Los martes antes de las 07:30 CDMX no se listan reportes abajo hasta el corte 07:30. Programador cada 5 minutos.
